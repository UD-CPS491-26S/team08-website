Sprints

Sprint 1

Month 1 Reflection:


For the first month of the project, a good portion of the first 2 weeks were spent discussing the logistics of the project such as project setup, environment setup, how pull requests will be handled, and what tech stack will be used. For the project management and collaboration, the team decided to use Trello as the means to handle all tasking required for the project. The alternative to Trello was Jira, but Trello was chosen because the team did not require the more advanced functionality that came with Jira, and since Jira took more setup time and was not free to use the team decided to use Trello instead. For pull requests (PR), the team decided to do a buddy system. What this means is that the team is split evenly into 2 sub-teams. One team will be handling the front-end (Justin and Bryan) and another team will be handling the back-end (Grant and Erich). When a team member makes a PR, they will ask for a review from their partner. In cases where a back-end team member needs to make changes to the front-end (or vice versa) in their PR, they will ask a member of the team for a review. The last of the project logistics that the team talked about was the tech stack. For this project, the team decided to go with a Vue, FastAPI, and PostgreSQL stack. Vue was chosen as the front-end framework primarily because of the customer. The customer primarily utilizes Vue in their projects and by having the application done in Vue, it will allow the customer to easily make updates to the application after it is passed on to them. A Python back-end was required for this project as most embedding projectors were made using Python. FastAPI was specifically chosen; it was primarily made for API, therefore having better performance and built-in documentation than alternatives like Flask. PostgreSQL was chosen because the team determined that a relational database was better than a non-relational database since structure was required for proper data analysis. PostgreSQL was chosen simply because it is the industry standard when it comes to relational databases.


Concurrent with discussing project logistics, the team was also performing research on key components for the application such as embedding projectors and mapping library. In regards to embedding projectors, there were a few that the team had looked into. These were TensorFlow’s Embedding Projector, Voxel51’s FiftyOne, Renumic’s Spotlight, and Apple’s Embedding Atlas. In the end the team chose to go with Renumic’s Spotlight. This was for a variety of reasons but the main reason was Spotlight’s easy setup, well designed UI, and it had all of the functionality required for the project. Embedding Atlas was a close second to Spotlight because of its integration with JavaScript thus not requiring its own standalone web application. However, its lack of a 3D view caused the team to go with Spotlight instead. TensorFlow’s Embedding Projector was ruled out because despite having the best looking UI and containing all of the functionality the team was looking for, it was quite complex to setup and update dynamically using Python API. FiftyOne was ruled out for the poor looking UI and lack of 3D representation. For the mapping library the team had two options: MapLibre and Cesium. Of the two, the team decided to use MapLibre. The main reasoning behind MapLibre was that it was much easier to integrate than Cesium into Vue and had faster loading and rendering. Fast loading and rendering is very important in this application as the application could be displaying thousands of points at once.


Towards the end of the month, the team began development on the application. With roughly 1 ½ weeks of development, the team was able to set up both the FastAPI server and the Vue application. The Vue application has the dashboard GUI completely set up with the mapping library partially integrated. The FastAPI server has working routes and has the standalone Spotlight application up and running with some fake data in it.


Month 2 Plan:


For Month 2, the team plans to have a minimum viable product complete and a demo ready for the customer. To complete this, the team will need to have the database setup, integrate all of the various components into the front-end, and start setting up the front-end to retrieve data from the database via the back-end.


In the front-end, there are 3 major feature additions that need to be done. These are the mapping component, the embedding component, and the timeline. The mapping component should use MapLibre to display all data from the database within a selected time range. Users should be able to select individual points which will highlight it and its respective embeddings within the embedding window. Users should also be able add pins at any point of interest. These pins should be saved within the database on loaded in whenever the user returns or refreshes the page. The embedding component needs to have the Spotlight web application integrated within it. The embedding components will need to hide as much of the Spotlight UI as possible leaving only just the embedding projector. The timeline component should allow the user to play through a timeline from the first data point to the last data point. As the timeline is progressing the data which both the embedding component and mapping component will need to update to show the data at the current time within the timeline.


In the back-end, there are 2 core functionality that needs to be implemented. The first functionality that needs to be implemented is the ability for the back-end to be able to forward data to the front-end. To this, the back-end will have to establish a connection to the PostgreSQL database and create GET routes for the front-end to call. These GET routes will need to allow the filtering of the retrieved data using the URL parameters. The other functionality that needs to be fully implemented is Spotlight. While the Spotlight standalone application is set up and running, there are a lot of UI components that are unnecessary for the project. The Spotlight standalone application will need to be cleaned up, removing as much of a clutter as possible. There also needs to be a way to update the Spotlight UI dynamically. This will be done using the Spotlight’s Viewer API.

Sprint 2

Month 2 Reflection:


During Month 2, the team shifted its focus from planning and environment setup to active development and system integration. The primary objective for this sprint was to deliver a minimum viable product that demonstrates the core functionality of the application. By the end of the sprint, the team successfully implemented and integrated three major components: a map visualization, an embedding visualization, and a timeline filtering system. These components establish a functional pipeline from database to user interface and validate the decisions made in Month 1.


The map component, developed using MapLibre, is capable of showing data points based on latitude and longitude values stored in the database. This confirms that the selection of MapLibre was appropriate, particularly due to its performance and compatibility with the Vue framework. The embedding component, powered by Spotlight, has been integrated into the application and is able to dynamically display data retrieved from the backend. Additionally, the timeline feature allows users to filter data based on time, with both the map and embedded components updating accordingly. This synchronization between components represents a significant milestone, as it demonstrates cohesive interaction between frontend and backend systems.


Several design decisions were made throughout the sprint to address emerging challenges. One massive issue involved not having the timestamp data in the initial dataset. Since the timeline feature required spotlight filtering with unix timestamps, this limitation needed to be resolved. After consulting with the client, the team updated the database schema and queries to include timestamp information. This ensured that the timeline functionality could operate as intended. Another consideration involved the capabilities of the Spotlight embedding tool. While Spotlight met most of the project’s requirements, its support for certain 3D features may be limited. The team decided to continue using Spotlight due to its overall strengths, with the understanding that any limitations could be addressed through alternative approaches in future development.


The team encountered several challenges during this sprint. A significant obstacle was reduced development time due to three team members attending the Game Developers Conference in San Francisco. This resulted in the loss of one week of development time and required the team to adjust its workflow to meet deadlines. Despite this setback, the team was able to complete the MVP by increasing coordination and effort toward the end of the sprint. Another challenge involved refining the Spotlight interface. The standalone application contains several unnecessary interface elements, requiring additional work to tailor it to the project’s needs.


From a project management standpoint, the team maintained consistent communication through scheduled meetings and ongoing discussions via Discord. Meetings held on March 17th and March 22nd were particularly important for assigning tasks and finalizing deliverables for the MVP demonstration. The team also continued to follow its established pull request review process, which contributed to maintaining code quality and consistency across the project.


Overall, Month 2 represents a successful transition from planning to implementation. The completion of the minimum viable product demonstrates that the chosen technologies and system design are effective and capable of supporting the project’s goals. While challenges arose, the team adapted appropriately and remained on track for future development.


Month 3 Plan:


For Month 3, the team will focus on refining the minimum viable product and expanding its functionality to better align with client expectations. The primary goal is to transition from a functional prototype to a more polished and complete application. This will involve improving user experience, enhancing interactivity, and addressing technical limitations identified during the MVP demonstration.


While the current integration of Spotlight is functional, it should be further improved to better the usability and visual consistency. The team plans to simplify the interface by removing unnecessary elements and changing the styling to better align with the overall application design. Additional UI will also be introduced to allow users to interact more effectively with the spotlight data, including improved filtering and clearer visual feedback.


The map component will also be expanded to include more advanced interaction capabilities. One planned feature is box selection, which will allow users to select multiple data points simultaneously. This enhancement will improve the analytical capabilities of the application and provide a more intuitive user experience. The team will also continue optimizing rendering performance to ensure that the application remains responsive when displaying large datasets.


User interface and user experience improvements will be a priority throughout this sprint. While the MVP demonstrates core functionality, further work is needed to ensure a cohesive and professional appearance. The team will focus on improving layout consistency, responsiveness, and overall usability. This includes strengthening the interaction between components so that user actions in one part of the application are clearly reflected across the entire system, for example selecting a data point on the map highlights it in spotlight.


In addition to technical development, the team will incorporate feedback from the client following the MVP presentation with them on March 23rd. This feedback will guide final adjustments and help ensure that the application meets both functional and usability expectations. By aligning development priorities with client needs, the team aims to deliver a solution that is both technically sound and practically valuable.


Based on current progress, the team is confident in its ability to meet the final product deliverable timeline. The successful completion of the minimum viable product indicates that the foundational components are in place, and remaining work primarily involves refinement and feature enhancement. With continued collaboration and effective task management, the team expects to complete all objectives for Month 3 and deliver a product that satisfies the project requirements.
